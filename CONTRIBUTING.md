# Contributing to Pretext Generator

Thanks for your interest in contributing to Pretext Generator. We believe good projects grow through collaboration, and we welcome contributions from beginners, designers, developers, testers, and anyone who wants to help improve the app.

This project is still evolving, and we are actively looking for ways to make it more useful, more stable, and easier to adopt by more people. Your ideas, bug reports, and improvements are valuable.

No contribution is too small. Whether you fix a typo, improve the UI, improve documentation, or propose a new feature, your work helps move the project forward.

## Ways to contribute

You can help in many ways:

- Report bugs and broken behavior
- Suggest features or UX improvements
- Improve documentation and examples
- Refactor code to make it cleaner and easier to maintain
- Add tests and validation
- Help with accessibility and usability
- Share the app with other users and contributors

## Community values

We want this project to feel welcoming and respectful for everyone.

- Be kind and constructive in discussions
- Assume good intentions
- Share feedback in a helpful, actionable way
- Focus on improving the project, not on personal preferences alone
- Encourage new contributors instead of intimidating them

If you are unsure whether your idea fits, open a discussion or issue anyway — we are happy to talk through it.

## Before you start

Please check the project documentation first:

- README.md
- spec.md (if needed for product requirements)
- Existing issues and pull requests

This helps reduce duplicate work and makes it easier to align with the current vision of the project.

## Local setup

1. Fork the repository.
2. Clone your fork locally:

```bash
git clone https://github.com/<your-username>/PretextGenerator.git
cd PretextGenerator
```

3. Install dependencies:

```bash
npm install
```

4. Run the development server:

```bash
npm run dev
```

5. Open the app in your browser at http://localhost:3000

## Development workflow

We recommend the following workflow for contributions:

1. Create a branch for your work:

```bash
git checkout -b feature/my-improvement
```

2. Make your changes in small, focused commits.
3. Keep your code readable and consistent with the existing project patterns.
4. Run linting before submitting your work:

```bash
npm run lint
```

5. If you make a production-related change, run a build check:

```bash
npm run build
```

6. Open a pull request with a clear description of what changed and why.

## Coding guidelines

We try to keep the project approachable and maintainable. Please aim for:

- Clear and readable code
- Small, well-scoped changes
- Descriptive commit messages
- Good naming conventions
- Minimal unnecessary complexity
- Respect for the current architecture and styling patterns

If you are new to the codebase, do not worry. We are open to contributors at every skill level. If you need help understanding a part of the project, just ask.

## Submitting issues

When opening an issue, include as much relevant information as possible:

- What happened
- What you expected to happen
- Steps to reproduce
- Browser or environment details
- Screenshots or recordings if useful
- Any relevant logs or console output

This makes it much easier to fix the problem quickly.

## Submitting pull requests

When you open a pull request, please:

- Use a clear and specific title
- Summarize the problem and the solution
- Mention any relevant issue numbers
- Keep the PR focused on one concern when possible
- Add context if the change affects UX, exports, layout, or performance

Good pull requests are easier to review and merge.

## Feature suggestions

We are especially interested in ideas that help the app become more practical and valuable to users. If you have a feature idea, please share it with a short explanation of:

- the problem it solves
- why it matters
- how it could fit into the project
- whether it is a small improvement or a larger change

We want to hear ideas from people who use the app, not only from developers.

## Documentation

Documentation matters. If you notice unclear instructions, confusing UI flows, missing examples, or outdated details, please improve them. Good docs are a huge part of making a project easier to adopt and grow.

## A note for first-time contributors

If you are contributing for the first time, please do not hesitate to ask questions. We are happy to help you get started, explain the codebase, and review a draft of your work.

We want contributors to feel comfortable, supported, and encouraged — not pressured.

## Project direction

This project is intended to be developed with a long-term vision: to make presentation and visual content generation easier, more polished, and more useful for real users. We welcome contributors who want to help grow it into a helpful and widely used tool.

If you are excited about this project and want to help build it further, we would love to have you involved.

## Final note

Thank you for considering contributing to Pretext Generator. Every contribution, whether small or large, helps the project become more useful, more stable, and more welcoming to others.

We are grateful for your time, your ideas, and your support.

If you are ready to contribute, open an issue, start a discussion, or submit a pull request — we would be glad to review it.
